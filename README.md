# 💍 Lista de Presentes de Casamento

Site de casamento elegante com lista de presentes integrada ao Supabase.

## Tecnologias

- **React 18** + **TypeScript**
- **Vite 4** (build tool)
- **React Router v6** (roteamento)
- **Supabase** — PostgreSQL, Auth, Storage, RLS
- **Vercel** — hospedagem e deploy
- **Git / GitHub** — versionamento

---

## Funcionalidades

| Área | Recurso |
|------|---------|
| Público | Página com nome do casal, mensagem, lista de presentes, status |
| Público | Copiar chave PIX com feedback visual |
| Público | Botão "Ver anúncio" abre link em nova aba |
| Admin | Login / logout via Supabase Auth |
| Admin | CRUD completo de presentes |
| Admin | Upload de imagem (JPEG/PNG, máx 5 MB) |
| Admin | Marcar presente como comprado / disponível |
| Admin | Editar configurações do casamento e chave PIX |
| Segurança | Row Level Security no banco |
| Segurança | ProtectedRoute no frontend |

## Instalação local

### Pré-requisitos

- Node.js ≥ 18 (recomendado) — o projeto também funciona em Node 16 com Vite 4

### 1. Clone e instale as dependências

```bash
git clone <seu-repositorio>
cd wedding-gift-list
npm install
```

### 2. Configure as variáveis de ambiente

```bash
cp .env.example .env
```

Edite `.env` e preencha com os valores do seu projeto Supabase:

```env
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

> ⚠️ **Nunca commite o arquivo `.env`.** Ele já está no `.gitignore`.

### 3. Execute localmente

```bash
npm run dev
```

A aplicação estará disponível em `http://localhost:5173`.

### 4. Build de produção

```bash
npm run build
npm run preview   # visualizar build localmente
```

## Configuração do Supabase

### Tabelas (já criadas)

As tabelas `gifts` e `settings` já existem no seu projeto com a seguinte estrutura:

```sql
-- gifts
create table public.gifts (
    id          bigint generated by default as identity primary key,
    name        text not null,
    description text,
    price       numeric(10,2) not null default 0,
    image_path  text,
    product_url text,
    purchased   boolean not null default false,
    created_at  timestamptz not null default now(),
    updated_at  timestamptz not null default now(),
    constraint  gifts_price_check check (price >= 0)
);

-- settings
create table public.settings (
    id              bigint generated by default as identity primary key,
    couple_name     text not null,
    wedding_message text,
    pix_key         text,
    created_at      timestamptz not null default now(),
    updated_at      timestamptz not null default now()
);
```

### RLS — Políticas de escrita para o administrador

As políticas de leitura pública já existem. Execute este SQL no **SQL Editor** do Supabase para habilitar as operações administrativas:

```sql
-- =====================================================
-- GIFTS: administrador pode inserir, editar, excluir
-- =====================================================
create policy "Authenticated users can insert gifts"
on public.gifts for insert
to authenticated
with check (true);

create policy "Authenticated users can update gifts"
on public.gifts for update
to authenticated
using (true) with check (true);

create policy "Authenticated users can delete gifts"
on public.gifts for delete
to authenticated
using (true);

-- =====================================================
-- SETTINGS: administrador pode editar
-- =====================================================
create policy "Authenticated users can update settings"
on public.settings for update
to authenticated
using (true) with check (true);

-- =====================================================
-- STORAGE: administrador pode fazer upload/exclusão
-- (substitua 'gift-images' se o bucket tiver outro nome)
-- =====================================================
create policy "Authenticated users can upload gift images"
on storage.objects for insert
to authenticated
with check (bucket_id = 'gift-images');

create policy "Authenticated users can update gift images"
on storage.objects for update
to authenticated
using (bucket_id = 'gift-images');

create policy "Authenticated users can delete gift images"
on storage.objects for delete
to authenticated
using (bucket_id = 'gift-images');
```

### Usuário administrador

No painel do Supabase, vá em **Authentication → Users → Add user** e crie o usuário que usará o painel administrativo.

### Configuração inicial

Se ainda não tiver inserido a linha inicial na tabela `settings`, execute:

```sql
insert into public.settings (couple_name, wedding_message, pix_key)
values (
    'Nome1 & Nome2',
    'Sua mensagem especial para os convidados',
    'sua-chave-pix'
);
```

Você pode editar esses dados a qualquer momento pelo painel em `/admin/configuracoes`.

### Nome do bucket de imagens

O bucket está configurado como `gift-images` em `src/services/supabase.ts`:

```ts
export const STORAGE_BUCKET = 'gift-images';
```

Se o seu bucket tiver nome diferente (ex: `gift-images-home`), altere essa linha e também as políticas de Storage acima.

## Deploy na Vercel

1. Faça push para o GitHub
2. Acesse [vercel.com](https://vercel.com) e importe o repositório
3. Em **Environment Variables**, adicione:
   - `VITE_SUPABASE_URL` → URL do seu projeto Supabase
   - `VITE_SUPABASE_ANON_KEY` → chave `anon` do seu projeto
4. Deploy — o `vercel.json` já configura o roteamento SPA
